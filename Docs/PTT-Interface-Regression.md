## 程式碼檢查結果

| 功能 | 實作依據 | 評估與驗證界線 |
| --- | --- | --- |
| 鍵盤操作 | `Lite/TermView.cpp` 的 `OnChar`／`OnKeyDown` | 傳送字元／按鍵對應；未依列表舊標籤決定操作。仍須人工確認游標與按鍵結果 |
| 滑鼠／手勢 | `Lite/MouseCTL.cpp` 的預設映射、`TermView.cpp` 的 `OnMouseWheel` | 滑鼠瀏覽模式映射 Enter／Left／Up／Down 等；一般滾輪主要操作本機捲軸。不是 SGR Mouse，也不代表點擊新版提示能直接執行指令 |
| 主選單／列表文字 | 已檢查 Lite／Resource 的 cpp、h、rc（按 CP950 解碼） | 未找到以「我是」「呼叫器」「選擇看板」「文章選讀」「鴻雁往返」等舊文字實作的硬編碼辨識；不代表使用者巨集／觸發器沒有依賴 |
| 看板資訊 | 一般按鍵傳送路徑 | 未發現專用的自動擷取看板資訊／任意鍵離開狀態機；新版需由使用者或巨集改用 q／左方向鍵 |
| 文章複製／動畫 | `ArticleProgress.h`、`GetArticleProgress`、`ContinueCopyArticle` | 已改為有界解析左側進度；新增測試確認舊／新／空白右側提示不影響結果，非文章底列不誤判完成 |
| 自訂觸發器 | `TelnetConn.cpp::CheckStrTrigger`、`TriggerList.cpp` | 對原始接收區塊比對位元組，非解碼後畫面；不是正規表示式。舊文字、空白、色碼改變或跨區塊／夾控制碼可能造成不命中 |

觸發器既有實作沒有完整的跨接收區塊比對／單次事件去重保證；本輪不改寫觸發器引擎。
`memstr` 的長度處理亦值得另案補強：目前先以 key 長度回退 end，再決定是否搜尋，較長 key 可能形成越出陣列範圍的指標。
這是檢查中辨識的既有風險，不能說因本輪測試已解決；若接下來要使用觸發器自動化，可先處理此項。

## 自動測試範圍

`Tests/ArticleProgressTests.cpp::InterfaceRegression` 使用公告格式製作合成資料，並非真實連線錄製：

- 舊／新看板、我的最愛、分類、文章、系列、文摘、信件、精華、主選單與看板資訊文字，不得視為文章完成。
- 完整中文進度以 Big5／UTF-8 編碼，搭配舊／新／隱藏按鍵提示，檢查 0%、50%、100% 與 80／120 位元組寬度。
- 可見底列之外即使附有文章進度文字，也不能越界讀取並誤判。

此處寬度是解析器的位元組邊界測試，不是 UTF-8 顯示欄寬正確性的驗收。
測試不驗證 MFC 繪圖、站台實際按鍵結果或使用者觸發器；這些留給下方人工驗證。
執行方式沿用 [測試文件](../Tests/README.md#文章複製自動測試)。

本輪結果：Debug／Release 文章測試各 783 項通過（原 557 項，新增 226 項）；
既有 Keep-Alive 各 884 項、CSI 各 8,896 項仍通過。正式程式未修改，未重編或操作 GUI。

## 自訂觸發器／巨集檢查

先備份；本輪未讀取或修改個人觸發器內容。檢查是否含有：

- 舊標籤「選擇看板」「文章選讀」「鴻雁往返」或標題括號內的固定空白。
- 主選單舊底列「我是」「呼叫器」「周」及固定逗號格式。
- 一整段右側提示、Row 1 固定提示、固定 ANSI 顏色序列。
- 進入 i 後用空白／Enter 退出的巨集：新版應以 q 或左方向鍵離開。

不要把所有規則一律替換成「文章列表」：新版搜尋結果、文摘、信件有不同標籤。
也不要直接套用正規表示式，現有觸發器不是 regex 引擎。
若需協助更新，提供去識別化的觸發條件與預期動作即可，勿提供帳號密碼或私信內容。
在真實站台只檢查條件，不用發文、刪除、管理或送訊息作為測試回應。
