## 行為與限制

- 辨識 7-bit OSC 起始 `ESC ]`，吸收到 ST（`ESC` 加反斜線，`0x1B 0x5C`）或 BEL。
- `OSC 8;params;URL ST` 開啟連結，空 URL 關閉。params（包括 id）可存在，目前不依 id 分組。
  保留的目標對應到標籤的每個位元組，只有使用者點擊才交給既有開啟網址流程；接收不發送回覆或請求網站。
- OSC 指定目標優先於標籤內看起來像網址的文字；未知 OSC 不改變目前的有效連結範圍。
  普通文字的自動網址辨識仍保留，與 OSC 範圍重疊的自動辨識不會再形成第二個目標。
- 只接受絕對 HTTP／HTTPS URL；拒絕其他協定、空主機、userinfo（`user@host`）、控制字元、空白、
  反斜線、引號、角括號及不完整的百分比跳脫。非 ASCII URI 位元組轉成百分比編碼，避免交給 ANSI 開啟流程時轉壞。
  不合法的非空目標仍佔有其標籤範圍，但不可點擊；不退回開啟標籤中的文字網址。
- 下劃線依既有超連結設定顯示；滑鼠點擊開啟目標，右鍵的「複製網址」取得真正目標。
  複製可見文字則仍取得標籤。右鍵選單先複製目標字串，避免開選單期間接收更新造成失效指標。
- ST 可以跨接收區塊，OSC 內嵌的 ESC／CSI／DEC2026 不會當成正常終端指令。
  BEL 只終止 OSC，不發出提示音；OSC 內 CR／LF／TAB／BS 等也不傳至畫面處理。
- CAN／SUB 取消 OSC，之後的位元組恢復一般文字／控制碼解析；這也適用於正在等待 ST 反斜線的狀態。
- OSC payload 最多保留 4096 位元組，只有完整且未超長的命令才解釋；超長內容不會溢位或釋出尾端文字。
  未終止字串會持續吸收至 ST／BEL／取消／連線重設，沒有依長度或逾時猜測結尾。
  若對方漏送結尾，後續文字可能暫時看不見；這是避免把未知控制內容誤當畫面的保守處理。
- 不把 8-bit `0x9C` 當作 ST，也不把其他高位元組解成 C1 指令，保留既有 Big5／UAO／UTF-8 行為。
- `OnClose` 與 `OnConnect` 清除 OSC／CSI 解析狀態與 Telnet 協商暫存，避免未完成序列影響下一次連線。
- 每連線最多保留 4096 個目標、合計 1 MiB 目標網址；畫面、作用中連結與同步快照共用目標物件，
  最後一個引用消失時歸還額度。超額的新目標視為不可點擊，仍正常顯示標籤。
- 網址跟隨列資料的身分與文字位置；覆寫、清除、字元插入／刪除、列搬移及 resize 同步更新對應。
  DEC2026 保存舊畫面的目標快照，同步中暫停命中；結束／逾時後配合當前畫面恢復。
- 原始資料觸發器仍採既有規則，本階段沒有把觸發器改成只比對可見文字。
  DCS 等其他字串協定仍未支援；本次不宣稱完整 ECMA-48 相容。
- 現有純文字／ANSI 複製與 ANSI 存檔不匯出 OSC 8 標記；載入原本含 OSC 8 的檔案可點擊，
  經既有 ANSI 存檔重建後不保留隱藏目標。UTF-8 顯示欄寬的既有限制亦不在本次重寫範圍內。

## 人工離線驗收

在專案根目錄執行：

```powershell
powershell -NoProfile -File Tests/New-OscVisualFixture.ps1
```

1. 一次只開一個組態的 PCMan，用「ANSI 編輯 → 開啟舊檔」開啟 `Tests/fixtures/OscCompatibility.ans`。
   fixture 載入時暫用覆寫模式以固定 EDIT 的預期文字，結尾恢復編輯器插入模式。
2. 第 3 行應為 `ST: BEFORE LABEL AFTER`；第 4 行為 `BEL: LABEL END`，不應看到 URL 或 `8;;`。
   開啟超連結下劃線時 LABEL 有下劃線；移到 LABEL 顯示手形。右鍵複製第 3 行目標，應為
   `https://example.com/?pcman=osc8-target`；點擊才會啟動瀏覽器。腳本本身不會開瀏覽器。
3. 第 5～7 行 UNKNOWN／INJECT／LONG 後只應看到 `OK`；畫面標題與其他行不能被內嵌清畫面指令清掉。
4. 第 8 行應看到 `CANCEL: CAN OK | SUB OK`；第 9 行的 `RED LABEL` 為紅色，後面的 `NORMAL` 為普通色。
5. 第 10 行 BLOCKED 的可見網址不得開啟或提供 OSC 目標；第 11 行 OVERRIDE 右鍵複製必須取得
   第 3 行的真正目標，不是 `https://visible.example/`。
6. 第 12 行 EDIT 應為 `ABXDE`，AB／DE 仍有連結，X 無連結；第 13 行 ERASE 完全沒有舊連結。
   第 14 行 INSERT 應為 `A  BCDE`，空隙不可點擊；第 15 行 DELETE 應為 `ADE`，三字仍可點擊。
7. 第 16 行中文每個可見字都指向同一目標；第 17 行相鄰 FIRST／SECOND 分別複製出 HTTPS／HTTP 的不同目標。
   以預設 Big5／UAO 模式開啟此 CP950 fixture；UTF-8 byte mapping 有自動測試，但不據此宣稱 UTF-8 繪圖已完整驗收。
8. 最後能看見 `END`，沒有 4096 個 x、HIDDEN 或其他 OSC 控制內容。選取複製只含可見標籤。
   關閉超連結下劃線後，點擊／右鍵複製仍正常；也驗證拖曳選字不意外開啟目標。
9. 依序在 Debug／Release 驗證；不要將 fixture 貼上或傳送至 BBS。本輪腳本及流程已由使用者確認正確，結果見上方「人工驗收紀錄」。

本機 ANSI 編輯器不啟用 DEC2026 呈現等待；OSC 內不會提前開關真實同步區的條件由自動測試驗證。
離線檔不能單獨驗證網路分段或實際重連，需搭配下方本機連線驗收。
本輪兩個腳本及流程均已由使用者確認正確，另已實際瀏覽 PTT，未發現特殊異常。

## 本機連線、同步與捲動驗收

```powershell
powershell -NoProfile -File Tests/Start-OscHyperlinkFixture.ps1
```

1. 60 秒內用新的 PCMan 測試連線開啟 `telnet://127.0.0.1:22328`。工具只監聽本機 IPv4，無登入流程；
   不使用含帳密、自動登入、巨集或觸發器的既存站台設定。Enter 步驟在 PowerShell 視窗操作。
2. A：逐位元組輸出仍顯示可點擊 LABEL；確認右鍵複製真正目標、不合法協定被阻擋。
3. B：先複製 OLD 的 `?frame=old` 目標；依提示開始同步，1 秒內舊畫面仍可見但不可命中，
   結束後 NEW 的右鍵目標為 `?frame=new`，不能拿舊文字開啟新目標。
4. C：依提示捲動後，連結與標籤一起移動；本機捲軸向上看歷史也應正確。
   切換分頁、縮放字體或視窗後，命中仍跟隨文字；終端欄數改變時另外檢查保留部分與裁切部分。
5. 最後腳本以未結束 OSC 斷線；重新執行腳本並重連後，標籤與普通文字應正常，不沿用舊目標或持續吞字。
6. 保留一般 PTT WSS 的文章瀏覽、選取複製、整篇複製、防閒置及取消操作回歸。沒有實際 OSC 輸出時，
   不把「PTT 畫面正常」當成完整 OSC 點擊驗證；用上面的本機 fixture 補驗。

腳本不讀取／記錄客戶端帳密，不自動開啟 URL。按 Enter 結束或停止腳本後釋放連接埠。
